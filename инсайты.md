# Инсайты — Объяснятор

Наблюдения, выводы и уроки из разработки проекта.

---

## Архитектурные решения и их причины

**Keyword scoring вместо embeddings**
Сознательный выбор для MVP: нулевая инфраструктура, никаких внешних зависимостей вроде Pinecone или Supabase pgvector. На практике keyword scoring работает достаточно хорошо когда пользователь задаёт вопросы в терминологии самого документа — а именно так и происходит при изучении материала. Embeddings нужны для семантического поиска ("как это называется по-другому?") — это Phase 2.

**sessionStorage вместо БД**
Полностью stateless backend — никаких пользователей, никаких данных на сервере. Всё в браузере. Для учебного инструмента это правильно: документы часто чувствительные (конспекты, книги), пользователь не должен беспокоиться об утечке данных. Ограничение: нет синхронизации между устройствами.

**Haiku для генерации, Sonnet для чата**
Квиз, карточки, практика — это batch-генерация: запустил один раз, ждёшь результат. Скорость не критична, но цена важна. Haiku в ~5x дешевле Sonnet. Чат тьютора требует качества и нюансировки — Sonnet здесь оправдан.

**Next.js App Router + Vercel**
Идеальная связка для этого проекта: serverless route handlers для AI-вызовов (нет холодного старта проблемы с Node), edge CDN для статики, автоматический CI/CD из GitHub. Beget и другой shared hosting исключены — они не поддерживают Node.js серверные процессы.

## Что сработало хорошо

- **3-колоночный layout** — интуитивен и не перегружен. Документ в центре, навигация слева, тьютор справа. Пользователь не теряется.
- **Демо-режим** — критически важен для онбординга. Пользователь видит живой продукт без необходимости загружать файл. Снижает барьер входа.
- **Quick-action кнопки** — "Квиз", "Карточки", "Практика" над чатом упрощают discovery функций. Пользователь не ищет функции в меню.
- **Chunk labels в сайдбаре** — видеть структуру документа помогает навигации. IntersectionObserver синхронизирует скролл с активным разделом.
- **"Объяснить" при выделении** — killer feature для плотных текстов. Пользователь выделяет непонятный абзац → тьютор объясняет именно его.

## Подводные камни

**pdf-parse и Edge Runtime**
Node.js-only модули несовместимы с Edge Runtime Vercel. Стандартный Next.js App Router пытается запустить роуты на edge — это конфликт. Решение (`serverExternalPackages` + `runtime = "nodejs"`) не очевидно из документации.

**Биллинг Anthropic**
Ключ и баланс — разные сущности. Можно создать 10 ключей с одного аккаунта без баланса — все вернут ту же ошибку `credit balance too low`. Это потеря времени при дебаггинге.

**OpenAI quota**
При переходе на OpenAI API столкнулись с тем же 429 (quota exceeded). Новый аккаунт на OpenAI тоже имеет rate limits на уровне tier-0. Урок: всегда проверяй billing перед интеграцией AI API.

**Чанкинг коротких документов**
Алгоритм оптимизирован под длинные документы (лекции, статьи). Для коротких текстов (<3 абзацев) chunk label = первые 80 символов текста — это не очень красиво. Некритично для MVP, но стоит учесть в V2.

## Уроки для V2

1. **Добавить embeddings** — семантический поиск резко улучшит качество retrieval для вопросов вне терминологии документа. Рассмотреть: Supabase pgvector или Pinecone.

2. **Аутентификация + облачное хранение** — сейчас данные в sessionStorage. Пользователь закрыл вкладку — потерял прогресс. Добавить auth (Clerk) + хранение документов/заметок в облаке.

3. **Прогресс обучения** — трекать что пользователь уже изучил (правильные ответы в квизе, пройденные карточки). Spaced repetition для карточек.

4. **Поддержка нескольких документов** — сейчас одна сессия = один документ. Нужен "workspace" с библиотекой документов.

5. **Streaming ответов тьютора** — сейчас ждём полного ответа. Streaming через SSE улучшит perceived performance особенно для длинных объяснений.

6. **react-markdown вместо самописного рендерера** — текущий `renderMarkdown()` в TutorPanel покрывает 80% кейсов, но падает на сложной вложенной разметке.

## Наблюдения о продукте

**Учёба vs развлечение**
Пользователь загружает скучную лекцию. Квиз превращает пассивное чтение в активное тестирование. Карточки дают структуру для повторения. Практические задачи создают момент "применения". Это не просто чат с документом — это учебный цикл.

**Язык = доверие**
Русскоязычный UI создаёт ощущение что инструмент сделан "для нас". Тьютор отвечает на языке пользователя (русский или английский) — это снижает когнитивную нагрузку.

**Grounding критичен**
Тьютор отвечает ТОЛЬКО по материалу документа — это не баг, это фича. Пользователь доверяет ответам, потому что знает: информация из его документа, а не из интернета. Для учёбы это важнее чем "умный общий AI".
